# ZR 4 — Observatory Glass design system

The website-like flat panel layout has been replaced by a native, premium
glassmorphic instrument interface. All product principles are unchanged:
no simulated reading is ever presented as a live measurement.

## Colour relationships (intentional)

| Role | Colour | Meaning |
|---|---|---|
| Observatory ink | `#050B08` / `#07130D` | Night base; makes glass and gold luminous |
| Instrument gold | `#D6B56D` | The single action/identity accent (brass-instrument analogue) |
| Signal mint | `#6EE7B7` | Gold's cool complement — *system-ready / local* meaning only |
| Amber | `#FFB86B` | Hardware-dependent modules (SDR) |
| Warm stone | `#C9BBA6` | Neutral graphite-family tint for sessions/records surfaces |
| Paper / muted sage | `#F2F5EC` / `#AFBDB0` | Text hierarchy on ink |

Gold = act/identify, mint = ready/local, amber = hardware-gated, stone =
records. Warning/error hues are reserved for real states. A colour never
changes meaning between screens, and there are no electric-blue gradients.

## Glass, without a blur library

Blur backdrops are expensive and inconsistent on low-end devices, and this
project builds offline (Termux). Glass is therefore layered translucency:

1. A static, very subtle aurora canvas (gold top-right, mint left, warm stone low).
2. Panels: translucent vertical gradient (`glassBrush`) + 1 dp **gradient
   hairline** (`glassBorder`: white light-catch → accent) + soft coloured shadow.
3. Floating chrome: the bottom navigation is an inset rounded glass pill;
   content scrolls under it instead of meeting a hard web-page footer bar.

## Navigation & iconography

Icons are precision **vector line icons drawn on Canvas** (`InstrumentIcon`:
crosshair, waveform, layers, info, lens, radio arcs, antenna, clock, gear,
export, check, lock, grid) — one stroke weight with round caps/joins. This
module ships no icon library, and no dependency was added for icons. No
emoji and no Unicode text glyphs are used as icons; every icon is paired with
a text label, and interactive semantics live on the containing control.
Each module keeps its own tint from the table above.

## Logo (PNG only)

The old vector `res/drawable/ic_zr4.xml` is deleted. The launcher identity is
now a premium PNG set generated by `tools/make_brand_logos.py` (Pillow,
4× supersampled): antenna mast + gold/mint RF arcs + `ZR 4` wordmark on
emerald-ink glass. Masters live in `docs/brand/`; Android densities are in
`res/mipmap-*` (legacy + round) with a PNG adaptive-icon foreground in
`res/mipmap-anydpi-v26`, and in-app marks in `res/drawable-nodpi/`
(`brand_mark.png`, `brand_lockup.png`). Regenerate after editing the script
and re-export the densities — never hand-edit a single density.

## Motion

Section changes cross-fade (340 ms); navigation pills and card selection
animate colour (240–260 ms). There are no continuous decorative animations:
the standby state is static, and the spectrum still shows an empty grid and
**NO DATA** — motion never fabricates a signal. Each screen has one primary
CTA (Overview: "Configure observation source"); other actions are secondary.

## Spectrum state model (interface state, not data)

The Overview spectrum pane is driven by the module selected on the Sources
screen — and by nothing else. `spectrumStateFor()` distinguishes **NO
SOURCE**, **NOT IMPLEMENTED** (optical, Wi-Fi/Bluetooth) and **HARDWARE
REQUIRED** (external SDR), each with its own waiting/empty explanation. In
every state the plot is an empty grid labelled **NO DATA** with an
unavailable frequency axis: no samples, peaks, levels, or units are ever
invented to fill it. The pane is titled "Spectrum", never "Live", until a
verified source is actually supplying samples.

## Findings evidence language

The Sessions screen carries an evidence-only Findings empty state. Findings
may be created only from acquired samples with source, time, units, and
configuration recorded; anything unverified is labelled **"candidate
detected"** — never a confirmed transmitter or protocol. Technical detail
belongs in a future finding-detail view, not on the overview.

## Type floor

Micro-labels (eyebrows, chips, statuses, axis captions) have a hard floor of
10.5sp/11sp so the instrument stays legible at system font scales; nothing
shrinks below that to make a layout fit.

## Adaptive-icon foreground

Legacy launcher PNGs keep the full tile (symbol + "ZR 4" wordmark). The
**adaptive-icon foreground is symbol-only**: launchers mask adaptive icons
(circle, squircle, teardrop), and the low wordmark would clip in round
masks. `tools/make_zr4_launcher_assets.py` separates the antenna/RF-arc
symbol from the wordmark at the transparent gap in the master artwork and
fits it inside 60% of the 108dp foreground canvas (within the 66dp safe
zone) at every density. Nothing is redrawn or re-proportioned.

## Shell, spectrum context, and selection semantics

The product identity now lives in a **pinned compact glass top bar**
(status-bar inset respected); screens scroll beneath it, so "where am I"
never scrolls away. Under the empty spectrum, a measurement-context strip
(source, observation time, frequency·level·units) shows explicit dashes
until real samples exist — the fields are present, values are never
invented. Navigation uses proper tab semantics, source cards behave as a
radio group, and both button styles expose the Button role.

Session copy is layered-accurate: the engine layer defines traceable
sessions/observations/analysis runs (algorithm, version, parameters,
outcome), but they are **not yet connected to this interface or persisted** —
Sessions says exactly that instead of implying storage is absent entirely.

## In-app brand placement (HD PNG, legible at size)

One artwork, three correct places: the **top bar** uses `brand_symbol.png`
(antenna/RF-arc symbol only — the title next to it already reads "ZR 4", and
wordmark lettering at ~50dp is illegible), **About** showcases
`brand_icon.png` (the finished launcher tile with the full lockup, large
enough to read), and the **launcher** uses the tile + symbol-only adaptive
foreground. In-app PNGs ship at 512px (>= xxxhdpi for their display sizes);
1024px masters remain in `docs/brand/` and everything regenerates from
`tools/make_zr4_launcher_assets.py`. Superseded `brand_mark`/`brand_lockup`
resources were removed from `res/` so the APK ships no duplicate artwork.

## Dashboard navigation model

Overview has **one primary CTA** ("Configure observation source" in the
status hero). The observation-channel cards are the navigation: tapping one
selects that module and opens Sources (Sessions opens the session
workspace), each card labelled with its status and an INSPECT affordance and
exposed as a Button with a full spoken description. A previous duplicate
button row (same destinations as the hero CTA and tab bar) and its now-dead
secondary button component were removed — every visible control now does
exactly one real thing. The spectrum header also carries the selected
source's icon and module tint, so the pane's state is readable at a glance.

## Enterprise Phase 1 — theme system, settings, splash, monochrome icon

Implemented on top of the merged RTL-TCP engineering main (this branch
contains `origin/main` plus the stages below; compile verification is via the
repository CI on a future PR — see README status).

### Centralized light/dark themes (`ZrTheme.kt`)

All colour tokens live in one file as getters over an active `ZrPalette`
(snapshot state, so composables **and** Canvas draw code follow a switch):

| Token role | Dark (Observatory night) | Light (warm paper) |
|---|---|---|
| Canvas (`Ink/InkDeep/InkLow`) | `#090D0A / #03070B / #07130D` | `#F6F2E6 / #E7E1CF / #FCF9F0` |
| Primary text (`Paper`) | `#F2F5EC` | `#1A241C` |
| Secondary text (`Muted`) | `#AFBDB0` | `#52635A` |
| Action gold (`Gold`) | `#D6B56D` | `#86651B` |
| Ready mint / hardware amber / records stone | `#6EE7B7 / #FFB86B / #C9BBA6` | `#0B7A54 / #99590C / #68573F` |

The dark palette is byte-identical to the previous hardcoded values; light
accents are deepened so paper/muted/gold/mint/amber text and the gold-button
label all measure **>= 4.5:1** (asserted in `ZrThemeTest`). Material3 gets a
matching `darkColorScheme`/`lightColorScheme`, so Material text fields and
dialogs track the same theme, and system-bar icon appearance follows the
active palette. The spectrum plot remains a dark instrument screen in both
themes (`PlotLine` grid), so trace contrast never depends on the shell theme.
Appearance mode (System/Light/Dark) persists in private SharedPreferences
(`ZrPreferences.kt`); System follows `isSystemInDarkTheme()` (including
runtime flips).

### Settings, Back behaviour, receiver defaults

Settings is a real fifth destination containing only behaviour-changing
preferences: the appearance radio group (applies instantly), the saved
RTL-TCP endpoint (Sessions capture fields now default to it and update it as
edited; connecting/capturing still happens only in Sessions), an accurate
local-data/privacy note, and the installed version from `PackageManager`.
System Back from any destination returns to Overview before exiting.

### Splash and launcher icon completion

`Theme.ZR4` (values / values-night) gives the launch window the correct
paper/ink background with transparent system bars for edge-to-edge;
values-v31 / values-night-v31 add the API 31 native splash showing
`brand_symbol` on the themed background — no artificial delay, no extra
dependency. Adaptive icons now use a genuine single-colour
`ic_launcher_monochrome` silhouette per density (generated from the symbol
alpha, safe-zone fitted) instead of reusing the colour foreground, so
themed icons tint correctly on light and dark launchers.

## Enterprise Phase 2 — task-first Home, workflow hierarchy, responsive hardening

### Home as an instrument dashboard

Overview opens on state + next action, not description: compact heading,
status hero whose single primary button starts (or inspects) work in
**Sessions** — where recording actually happens — then an
**Instrument status** panel built only from verifiable device truth:
`PackageManager` Wi-Fi/Bluetooth-LE feature presence, current permission
grants (read-only here; requests stay contextual in Sessions), the saved
RTL-TCP endpoint labelled *saved · not connected*, local SQLite readiness,
and the shell's latest analysed frame (samples · time · relative dBFS) or
its honest absence. State is conveyed in text, never colour alone. Phone
layouts list the four channels as compact single-line **action rows**;
>=580dp keeps the 2x2 summary cards — same destinations and semantics.

### Sessions workflow hierarchy and dialogs

One gold primary per screen is now enforced in Sessions ("Start observation
session"); RTL-TCP capture, Wi-Fi snapshot, BLE scan, close, and field-note
actions are secondary glass buttons with unchanged callbacks, permission
flows and duplicate-start guards. `ReceiverInput` (pure, unit-tested)
validates host shape, TCP port range, positive Hz values, and power-of-two
sample counts: the RTL-TCP dialog shows inline errors/supporting text and
keeps *Capture and analyse* disabled until all fields are well-formed; the
import dialog flags malformed optional values without blocking the
engine-validated path. All dialogs scroll and apply `imePadding()`, numeric
fields use numeric keyboards with Next/Done actions, and engines retain
their own authoritative validation.

### Responsive strategy

A navigation rail was evaluated and deferred with cause: with five
destinations the floating bottom bar remains reachable and legible at every
width, so the shell instead caps measures — content centered at 920dp, top
bar at 952dp, nav pill at 560dp — preventing stretched lines and edge-to-edge
panels on tablets/foldables while keeping one navigation model. Header
identity, nav labels, and session titles ellipsize under narrow widths and
large font scales instead of clipping or displacing controls; touch targets
remain ~48dp+ (buttons 52dp, nav items ~49dp, action rows ~62dp).
